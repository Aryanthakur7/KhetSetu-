Design notes:
- All application settings use the env prefix `KHETSETU_`. Hugging Face standard variables stay unprefixed through `validation_alias`: `HF_TOKEN`, and `HF_SPACE_ID` with `SPACE_ID` as an alias (HF sets `SPACE_ID` inside a running Space).
- The ENV VAR NAME, not the Python field name, is what users must see in errors. pydantic validation error locations carry the field name or alias; map back to the env var name through `Settings.model_fields`.
- `pydantic.ValidationError` string output can contain rejected input values (a secret could leak). Never call `str(exc)` on it for user output; build the message only from each error's location and message.
- The hello-world app and every later entrypoint load settings once at startup and pass the object down; there is no module-level global settings object.
- Tests must be hermetic: a developer's real `.env` (which may hold HF_TOKEN) must never be read by tests. Tests that call `load_settings()` or the CLI use the `isolated_cwd` fixture or pass `env_file=None`.
</context>
