## Phase Goal

**As a** developer, **I want to** push a change and watch it pass CI and run on a deployed hello-world Space, **so that** hosting, packaging and LLM funding are proven before real features are built.

**This plan's slice:** everything needed to deploy and verify the hello-world Space is built and proven locally, with no Hugging Face account, token or network access to the Hub required. The live attempt on the real account is plan 01-07.

<objective>
Deliver the tooling half of FND-05: a Space bundle builder, a Space-faithful local rehearsal that proves the monorepo packages run on a Gradio Space, and a probe tool for the live account, plus the architecture and hosting documentation and the final README.

Purpose: keep every plan except 01-07 independent of the human-held Hugging Face token. By proving packaging locally first (including the `sys.path` fallback that the Gradio-SDK install order may force), the live spike in 01-07 only has to answer the questions that genuinely need the account: can it create the Space, does the build succeed, and how will the LLM be funded.

Verified facts (checked against the installed packages during planning):
- `huggingface_hub` 2.3.0 provides `HfApi.create_repo` with `space_sdk`, `space_hardware`, `private`, `exist_ok` and `space_variables`; `HfApi.upload_folder`; `HfApi.add_space_variable`; `HfApi.get_space_runtime` (stage values include RUNNING, BUILDING, BUILD_ERROR, RUNTIME_ERROR, CONFIG_ERROR, NO_APP_FILE, APP_STARTING, RUNNING_APP_STARTING, STOPPED, PAUSED); `HfApi.fetch_space_logs(repo_id, build=False, follow=False)` returning an iterable of log lines; `HfApi.whoami`. `SpaceHardware` includes `cpu-basic` and `zero-a10g`. `InferenceClient.chat_completion` exists (and `.chat.completions.create`).
- `uv export` supports `--locked --no-dev --no-hashes --no-emit-workspace --package khetsetu`.
- Assumption under test, not a fact: HF's Gradio-SDK build installs `gradio[oauth,mcp]==sdk_version` first and then `pip install -r requirements.txt` from a copy of the file placed OUTSIDE the repository, so relative local paths such as `./backend` in requirements.txt are expected to fail. The rehearsal mimics that order; plan 01-07 confirms it against the real build logs.
- The same `app.py` works in two modes: dev (packages installed editable, path shim is a no-op) and Space bundle (only third-party deps installed, shim prepends the three `src` directories). The bundle keeps the repo layout (`contracts/src/...`, `backend/src/...`, `frontend/src/...` next to `app.py`).

Tooling conventions:
- `scripts/` is a package (has `__init__.py`) so `python -m scripts.<name>` and test imports work (pytest `pythonpath = ["."]`).
- Scripts print machine-readable JSON to stdout (ruff T201 is relaxed only under `scripts/`) and diagnostics to stderr.
- Generated artefacts go under `build/` (gitignored). Never write outside the repo or the system temp directory.
- Build any token-shaped test data at runtime from fragments; never commit a token-shaped literal.
