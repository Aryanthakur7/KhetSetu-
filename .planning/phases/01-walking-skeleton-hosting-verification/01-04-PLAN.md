## Phase Goal

**As a** developer, **I want to** push a change and watch it pass CI and run on a deployed hello-world Space, **so that** hosting, packaging and LLM funding are proven before real features are built.

**This plan's slice (the walking-skeleton tracer):** a user uploads a leaf photo in a running Gradio app and sees a result produced by a fake diagnosis service, with the frontend, the typed contracts layer, the backend fakes and a single composition root all exercised end to end.

<objective>
Build the thinnest real path through every layer the product will use (FND-06): `frontend/` renders, `contracts/` defines the DTOs and Protocols, `backend/` supplies fake services, and `app.py` is the one place they meet.

Purpose: this is the architecture every later phase fills in. Phase 4 replaces the fake `DiagnosisService` at the composition root without touching the frontend; a later two-Space split replaces in-process services with an HTTP client behind the same Protocols. The fake is deterministic and image-derived so tests can drive every outcome state (diagnosed, low confidence, not a leaf, unsupported crop) and the contract invariant "a refusal never carries a disease name" (the core value) is encoded in the DTO itself.

Output: contracts models/errors/protocols, backend fakes and container, frontend ui/presenters/messages, `app.py`, and unit plus end-to-end tests.

Out of scope (B-07): any real model, RAG, scraping or chat. No `ChatService` contract is defined yet.

Locked brief decisions honored:
- B-01: separate packages, typed `contracts/`, one composition root (`app.py`), enforced by import-linter (plan 01-03).
- B-06: Gradio 6.30.0 (launch-time options, messages-format conventions), `pillow>=12,<13`, Python 3.12.
- B-07: fake services behind `contracts/`.
- B-02: strict typing, tests at unit and end-to-end level.
</objective>

Verified facts about the pinned stack (checked against the installed packages during planning):
- Gradio 6.30.0: `gr.Blocks.launch` accepts `server_name`, `server_port`, `max_file_size`, `ssr_mode`, `show_error`, `theme`, `css` (theme/css/js moved from `Blocks()` to `launch()` in Gradio 6). `gr.Image` accepts `type`, `sources`, `buttons`, `webcam_options`, `format`, `height`. `Blocks.queue` accepts `max_size` and `default_concurrency_limit`. `gradio_client` 2.7.2 ships with gradio.
- Gradio 6 `Chatbot` and other 5.x conventions in older tutorials do not apply; do not copy v5 snippets.
- `ssr_mode` defaults to None (environment-driven); set `ssr_mode=False` explicitly so the app never depends on a Node runtime on a Space.
- Pillow is pinned `>=12,<13` (Gradio requires `<13`). Pillow lives in the backend only; contracts and frontend must not import it.

Conventions for this plan:
- Image upload crosses the seam as encoded bytes (`DiagnosisRequest.image`), not a PIL object, so `contracts/` stays pure pydantic, EXIF/orientation handling stays in the backend (Phase 4), and a later HTTP split needs no contract change. The frontend uses `gr.Image(type="filepath")` and reads the bytes.
- Frontend tests use tiny local stub services that implement the contract Protocols; they never import backend fakes.
- Test module basenames stay unique across the repo (`test_contracts_*`, `test_backend_*`, `test_frontend_*`).
- Use `typer.echo`/`sys.stderr.write` for output: ruff forbids print.
- Do not write negative-grep style checks for forbidden imports; the import-linter contracts from plan 01-03 are the gate (run via `make imports`).
