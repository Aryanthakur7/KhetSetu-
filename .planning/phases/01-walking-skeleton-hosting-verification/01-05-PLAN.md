## Phase Goal

**As a** developer, **I want to** push a change and watch it pass CI and run on a deployed hello-world Space, **so that** hosting, packaging and LLM funding are proven before real features are built.

**This plan's slice:** any dev, training or evaluation entrypoint starts by making sure `Project-AgML/plant_village_classification` is present (downloading it once if not, reusing it silently afterwards), while the deployed Space and CI never download it.

<objective>
Deliver FND-03: "Developer can run any training, evaluation or dev entrypoint and have the dataset downloaded first, idempotently and from cache when already present".

Purpose: Phases 2 and 3 are all dataset work. Making the download a single, tested, cached, integrity-checked function that every entrypoint is forced to call (by a decorator plus a policy test) removes the class of bug where a script silently runs on a missing or partial dataset, and keeps the 823 MB out of the Space (STACK.md finding 5).

Output: `khetsetu_backend.data` (manifest, `ensure_dataset`, summary, guard), `khetsetu_backend.bootstrap.prepare_runtime`, `khetsetu data inspect` and `khetsetu data download` CLI commands, the pinned manifest, `app.py` wiring, tests including an opt-in network test, and `docs/dataset.md`.

Locked brief decisions honored:
- B-04: the dataset is downloaded FIRST by every training/eval/dev entrypoint via an idempotent, cached `ensure_dataset()`; the deployed Space does NOT download it; the existing local copy under `data/plant_village_classification/` is recognised and reused.
- B-02: typed, tested, documented.
- B-07: no real model work; the only consumer of the data in this phase is `data inspect`.
</objective>

Grounded facts about the existing local copy (read from `data/plant_village_classification/.cache/huggingface/` during planning):
- It was downloaded with a `local_dir` download (the Hugging Face tool writes resume metadata under `.cache/huggingface/` inside it), at dataset commit `cb08789a92460034ced0449eac1dba72bb4883da`.
- Files and values (sizes in bytes, sha256 from the Hub tree record): `README.md` size 4193 (no sha256 recorded; it is not an LFS file); `data/train-00000-of-00002.parquet` size 431265906, sha256 ff914e1bc5c7c4467377ca4a28ab2bc06f79afd735300d2ee61e6a376bd52dbf; `data/train-00001-of-00002.parquet` size 431631981, sha256 f6b6b6e17050e6aa1e20c2a16de80bde00a64911ac46c4e8a463ec1f51176cf3.
- Dataset card facts (README front matter): one `train` split, 55448 examples, 39 classes with ids 0..38 (class 4 is `Background_without_leaves`).
- Re-verify rather than trust: the executor must recompute sha256 of the local shards and compare with the values above AND with the Hub (`HfApi().dataset_info(repo_id, revision=..., files_metadata=True)` exposes per-file size and LFS sha256) before committing the manifest.

Execution notes:
- `data/` is untracked, so an isolated git worktree will not contain it. In that case set `KHETSETU_DATA_DIR` to the absolute path of the main checkout's `data` directory for verification commands, or accept one 823 MB download (which also proves the download path).
- `huggingface_hub` honours `HF_HUB_OFFLINE=1`; use it to prove the cache-hit path needs no network.
- Importing `pyarrow` and `yaml` is allowed only in `data/summary.py` (extra `data`); `data/__init__.py`, `ensure.py`, `guard.py` and `bootstrap.py` must not import them, so the Space process never needs them.
- Use `typer.echo` for CLI output (ruff forbids print). Exit codes: 0 success, 2 invalid configuration, 3 dataset problem.
